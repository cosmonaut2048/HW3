#### Почему для модели используется `st.cache_resource`, а для таблиц – `st.cache_data`? 

`st.cache_resource` кэширует тяжёлые объекты, которые не сериализуются и должны существовать в единственном экземпляре на процесс. Streamlit хранит сам объект в памяти и раздаёт его всем сессиям/пользователям.

`st.cache_data` кэширует объекты, которые сериализуются. Streamlit копирует их при каждом возврате из кэша чтобы одна сессия не могла испортить данные другой. 
Для `test.csv` (DataFrame) и `p_test` (numpy-массив) это правильный выбор.

#### Что изменится, если вызвать `joblib.load` без декоратора?

Streamlit перезапускает `app.py` сверху вниз на каждое действие пользователя. Без декоратора `joblib.load('model.joblib')` выполняется при каждом перезапуске, интерфейс тормозит.

С `@st.cache_resource` модель загружается один раз при первом запуске и затем переиспользуется всеми перезапусками и сессиями.
